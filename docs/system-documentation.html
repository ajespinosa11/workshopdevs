Chapter 1

System Overview

The Makerlab Workshop Management System is a full-stack web application built with Next.js 16 that streamlines the end-to-end process of managing workshop registrations, sessions, check-ins, and customer data for a state-of-the-art 3D printing and maker experience hub.

What the System Does

🏭 Workshop Operations Platform

Manages the complete lifecycle of a workshop — from public customer discovery and booking, through staff session management and customer check-in, to post-session analytics and reporting.

🔄 Multi-Channel Booking

Accepts reservations from three distinct channels: Shopify Online Store (e-commerce), StoreHub POS (in-store payments), and Manual Walk-In registration by admin staff.

⚡ Real-Time Capacity Management

Uses a 15-minute soft-lock mechanism to temporarily hold a customer's seat during checkout, preventing overbooking on popular sessions. Auto-cancels expired soft-locks.

Chapter 6

Workshop Booking (Print 2 Profit)

🔗 localhost:3000/print-2-profit → src/app/(public)/print-2-profit/

The main booking page where customers select a workshop session and submit their registration. Features an interactive calendar with color-coded availability and a 15-minute seat soft-lock system.

📅 Month Calendar Picker

An interactive calendar displays all upcoming sessions. Each day with sessions shows a colored dot:

  • Green = Available seats
  • Orange = Almost full (≤5 seats)
  • Red = Fully booked / Sold out
  • Gray = No session scheduled

⌛ Time Slot Selection

After clicking a date, available time slots appear. Each slot shows workshop name, start time, end time, and remaining seats. Sold-out sessions display a "SOLD OUT" badge and are non-selectable.

📝 Booking Registration Form

After selecting a session, a modal form opens:

  • Full Name — Customer name
  • Email Address — For confirmation email
  • Phone Number — Contact number
  • Number of Participants — Pax count
  • Branch Location — Venue selection
  • Special Notes (optional)

⏱ 15-Minute Soft-Lock Timer

Once the form is submitted, a visible countdown timer appears. This soft-lock holds the seat while the customer completes payment. If the timer expires, the lock is released and the seat becomes available again.

⚠
Capacity Note: Bookings create a WorkshopRegistration with status AWAITING_PAYMENT. The soft-lock decrements availableSlots. If payment is not received within 15 minutes, the system auto-cancels the registration and restores the slot.

For PAID_FOR_ADMIN_VERIFICATION registrations: click "Verify Payment" to confirm payment and assign a session. Status changes to RESERVED and a confirmation email is sent.

📅 Assign / Change Session

Admin can assign a session to a registration with no session, or reschedule an existing booking to a different date/time slot.

Chapter 15

Discount Codes

🔗 /admin/discounts → src/app/admin/discounts/DiscountsManager.tsx

Generate one-time-use alphanumeric discount codes tied to specific events (trade shows, partner promotions). Customers use these codes during checkout to access free or discounted workshops.

How Discount Codes Work
1
Admin Creates a Batch
Enter an event name and a quantity (1–50). The system generates unique random codes all tied to that event.
2
Distribute to Attendees
Copy codes and share them with event attendees, partners, or sponsors. Each code is single-use.
3
Customer Redeems Code
Customer enters the code on the booking page. System validates and applies the discount.
4
Code Marked as Used
Upon redemption, isUsed = true and usedAt is timestamped. Cannot be reused.

📋 Events Panel (Left)

All events listed on the left, grouped by event name, showing total codes, used count, and unused count. Clicking an event shows its codes on the right.

🔑 Codes Table (Right)

Shows all codes for the selected event. Each row: code string, used/unused status badge, and the date used. Codes can be copied to clipboard with a single click.

➕ Generate Form (Top)

Enter an Event Name, set a Quantity (1–50), and click "Generate". Codes are auto-generated with unique random suffixes. Max 50 per generation batch.

A dedicated dashboard for tracking all complimentary and free-entry workshop reservations. Aggregates records from multiple sources into a unified view with an interactive calendar.

Data Sources — How Records Are Identified as "Free"

📦 Booking System

Free bookings from the voucher system where the voucher code starts with MLWS-FREE. These come from the Booking table.

📋 Registration System

Registrations with salesChannel = 'WALK_IN_FREE' or 'COMPLIMENTARY', or those with a SKU containing "FREE". These come from WorkshopRegistration.

📅 Free Sessions

Workshop sessions where the module name, description, or notes contain the word "Free" (case-insensitive) are shown in the sessions calendar panel.

📅 Calendar View

An interactive calendar shows all sessions designated as free workshops. Clicking a session date reveals the session details and attendee list including reservation source, status, and participant count.

📋 Reservation List

Unified table from both sources. Columns: Booking Reference, Customer Name/Email/Phone, Session (date, time, module), Status, Source (BOOKING_SYSTEM vs REGISTRATION_SYSTEM), Participants, and Date Created.

Receptionist Check-In Station

🔗 /receptionist → src/app/receptionist/client.tsx

A streamlined 3-step process for verifying and checking in customers on the day of their workshop. Designed for speed — staff can check in a customer in under 30 seconds.

🔗 Receptionist Navigation Bar

Three links:

  • Check-in → /receptionist (the check-in station)
  • Walk-ins → /receptionist/walk-in (walk-in processing)
  • Calendar Roster → /receptionist/today (session roster view)

3-Step Check-In Flow
🔍

Step 1: Search

Receptionist enters the customer's Booking Reference Number (e.g. P2P-LOCK-853656-4812). The system searches both WorkshopRegistration and Booking tables simultaneously.

📋

Step 2: Verify

The system displays full reservation details: customer name, email, phone, participants, payment status, reservation status, session date/time. Any validation issues are highlighted in a warning block with specific guidance.

✅

Step 3: Confirm

If all validations pass (paid + reserved + today's date), the green "Confirm Check-In" button activates. Clicking it marks the registration as ATTENDED, records the check-in time, and shows a success screen.

Validation Rules
CheckCondition RequiredError If Failed
Payment VerifiedStatus must be PAID_FOR_ADMIN_VERIFICATION, RESERVED, CONFIRMED, CHECKED_IN, or ATTENDED"Payment status is NOT VERIFIED"
Not CancelledStatus must not be CANCELLED, CANCELLED_BY_CUSTOMER, REFUNDED, or DUPLICATE_ORDER"This reservation is currently CANCELLED"
Not Already Checked InStatus must not be CHECKED_IN, ATTENDED, or COMPLETED"Customer is ALREADY CHECKED IN"
Reserved StatusStatus must be RESERVED, CONFIRMED, or PAID_FOR_ADMIN_VERIFICATION"Reservation status is X (Must be Reserved)"
Today's SessionThe session date must match today's date"Schedule date is [date], which does not match today"
✅
Auto-fill from URL: When staff clicks "Check In →" from the Calendar Roster, the system navigates to /receptionist?bookingReference=XXXX which automatically populates and initiates the lookup — no manual typing required.

Next to each customer, a "Check In →" button navigates to /receptionist?bookingReference=XXXX which pre-fills the check-in station for instant lookup and check-in.

📊 Session Summary Bar

Each session card shows: total capacity, booked count, checked-in count, and remaining open seats. A visual progress bar shows occupancy percentage.

ℹ
Combined Data: The roster combines both Booking records (from the voucher system) and WorkshopRegistration records (from Shopify/StoreHub/manual) into a unified attendee list for each session.

Chapter 21

External Integrations

Shopify Integration

🋥 Shopify Webhooks (/api/webhooks)

When a customer completes a purchase on Shopify, a webhook event is sent. The system:

  1. Extracts customer info, order number, SKU, and amount
  2. Creates or updates a ShopifyOrder record
  3. Matches to the existing WorkshopRegistration
  4. Updates status to PAID_FOR_ADMIN_VERIFICATION
  5. Triggers admin notification for review

📦 SKU Mapping

The system uses product SKU BW001 as the default workshop booking SKU. All registrations in the admin page are filtered by this SKU. Different workshop types can use different SKUs.

StoreHub POS Integration

🏪 StoreHub Sync (/api/storehub/sync)

Pulls transactions from the StoreHub POS system. Triggered manually by clicking "Sync" in the Plan Requests page, or automatically via scheduled background jobs. Matching transactions auto-approve pending requests and generate vouchers.

💌 Email Notifications (Nodemailer)

Transactional emails configured via environment variables (SMTP credentials in .env). Emails sent for: booking confirmation, voucher delivery, and admin-triggered resends.
